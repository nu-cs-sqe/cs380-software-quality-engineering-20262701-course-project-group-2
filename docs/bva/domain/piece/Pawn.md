## Step 4: Test Cases

**Purpose / use:** Creates an independent `Pawn` for board snapshots or simulated board states.

**Expected behavior:** Returns a distinct `Pawn` object with the same color as the original piece.

### Method under test: `getValidMoves(Location from)`

**Purpose / use:** Generates the Pawn's geometric forward destinations before Game applies occupancy and capture rules.

**Expected behavior:** Returns the squares the `Pawn` can reach using only its own movement rules and the board boundaries: one square forward, plus a second square forward while `from` is still on the pawn's start row (row 6 for WHITE, row 1 for BLACK). The direction comes from the piece's own colour and location.

Cases M68–M71 exercise edge files one step from the final rank. Cases M74 and M75 explicitly document the current behavior when a Pawn is placed on the final rank: no geometric forward destination is returned. Promotion is deferred and is not performed by `getValidMoves(Location)`.

Board-occupancy cases M3, M4, M5, M40–M43, and M82–M84 are documented under [`Game.getLegalMoves(Location)`](../Game.md), because geometric Pawn movement does not read other squares.
